🎯 Learning Objectives

  • Frame algebraic equations corresponding to a scenario and operate on them.
  • Perform algebraic operations across equations with multiple variables.
  • Calculate the value of variables from an equation, or a group of equations.
  • Identify algebraic patterns in riddles/puzzles and solve them.
  • Solve linear equations in two variables.

✅ Assumed Prerequisites

  • Can form an algebraic expression from a described scenario.
  • Can solve a linear equation in one variable.

📐 Grade & Curriculum Alignment

Sits within NCERT Grade 8's "Algebra Play," extending the chapter's own letter-number reasoning (Number Pyramids, Fun with Grids) into two-variable, real-world systems — the same style as the chapter's end-of-section problems (e.g. horses-and-hens, calendar magic), built out as a taught, interactive experience rather than a written exercise. The sequence deliberately departs from the textbook's section order to build toward two-variable systems purposefully, rather than sampling every section.

🧭 The Teaching Journey

Hook
A relatable checkout puzzle — Rajesh needs the right mix of fruits to match a known weight and price.
Core Interaction · Applet 1
Adjust quantities, see immediate weight/price feedback, discover guess-and-check works but is slow.
Core Interaction · Applet 2
A two-stage system — solve for unit weights first, then use a third constraint to pin down exact counts, then encode the result as a passcode.
Misconception Targeted
That problems with more than one unknown can only be solved by trial and error.
💡 Aha!
One equation can't pin down two unknowns — there are always many pairs that fit. To solve for two unknowns, you need at least two equations. That's the one idea both puzzles are built to reveal.

🤖 How the LLM Was Used

  • Scope was defined upfront: chapter/module selection, storyboard design (in PPT), pedagogical decisions, the tutor PPT, and the activity log were done independently; Claude's role was building the interactive HTML from those storyboards, sanity-checking the math, and this submission page.
  • Both applets were built by iterating in screenshot-and-fix cycles against the hand-made storyboards, not generated from scratch.
  • This process caught a genuine flaw in Applet 2's puzzle math (two valid solutions where only one was intended) before it reached a final build.

🛠️ Developer Notes

  • Both applets are single self-contained HTML files — no external assets or network calls — for safe offline, plug-and-play classroom use.
  • Built to a fixed 1220×690 canvas that scales to fit any screen without scrolling; shared color and layout conventions across both applets for visual consistency under the ClassRoots Edu brand.
Applet 2's original constraint set had two valid mathematical solutions; this was caught during the build process and patched by adding one more clue (a ≥ b) to the puzzle text — the full trail is in the activity log.
